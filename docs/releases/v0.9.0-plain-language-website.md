# Plain-language website revision — 2026-10-28

The public introduction now explains what a visitor installs, which task MESA
performs, and which task remains with the application. The same layout and
content are maintained in English and Turkish.

## Browser feedback addressed

| Comment | Result |
| --- | --- |
| 1: installation missing from the hero | The first screen includes the pinned pip command and `mesa start`, with copy controls. A separate disclosure explains the second terminal, document ingestion and search. |
| 2: empty, abstract boxes | The overview shows an actual policy file, its text, the Core operation, a customer question and the source returned to the application. |
| 3: unclear demonstration | The long animated dependency scenario is replaced by a labelled, connected document → Core → application diagram. |
| 4: status link looks like an in-page control | Alpha status is static text, with a separate underlined “Open project status” link. |
| 5–6: duplicated explanations | The repeated four-state scenario and its autoplay code were removed. How it works contains one three-step document example and one revision comparison. Database internals remain on Architecture. |
| 7: repository roles are unclear | Ecosystem separates the ordinary document/Core/application path, the optional legal example and the QA/certification tools. Each repository has a short role, input/output and relevant links. |
| 8: resources has no purpose | Resources now routes people by task: install, follow lessons, look up a term or follow a practical guide. Research/methods are secondary; planned tools are clearly labelled. |

The FAQ now answers eight practical first-use questions. The repeated closing
promotion was removed from the shared footer. Section headings and metadata for
all resource indexes use concrete descriptions rather than publishing slogans.
